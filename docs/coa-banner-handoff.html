Which products get it

All of them, minus a named exclusion list.

The snippet originally carried a hand-maintained list of thirteen SKUs. That meant every product added or overlooked afterwards silently had no banner — 31 of 44, including Cagrilintide, Retatrutide 20 mg, BPC-157 and TB-500. The rule is now inverted: everything is covered, and only exceptions are named. New products are covered the moment they are published.

Currently excluded — 10 products, 4 fragments

OP-AUX-BACWATER-10ML — Bacteriostatic Water, research support rather than an analysed material.
OP-BUNDLE-, OP-STACK-, OP-STK- — the three Build Your Research Bundles, the four Collections, Advanced Multi-Pathway and the Cellular Research Panel. One COA cannot describe a box the buyer composes.

Entries match as case-insensitive substrings, so those prefixes cover the next bundle too. The 6-vial kits (OP-KIT-*) are deliberately not excluded — six vials of one material, which a single COA does describe.

To exclude another 
add_filter( 'opl_coa_banner_exclude_skus', function ( $skus ) {
    $skus[] = 'OP-MET-EXAMPLE-5MG';
    return $skus;
} );

One list feeds all three surfaces, so a SKU added there drops out everywhere at once.

Checking it, now or later

Bust the cache. The site serves cached HTML to plain requests — that is what made the banner look missing on the first check after install. And grep -c counts matching lines; the catalog page is minified onto one, so counting there needs grep -o … | wc -l.

curl -s -H 'Cache-Control: no-cache' \
  "https://www.oligopolypeptides.com/products/cagrilintide-5mg-research-peptide/?nc=$(date +%s)" \
  | grep -c 'class="opl-coa-banner"'          # expect 1

curl -s -H 'Cache-Control: no-cache' \
  "https://www.oligopolypeptides.com/product-category/metabolic-research/?nc=$(date +%s)" \
  | grep -o 'class="opl-coa-pill"' | wc -l    # expect one per card

How it was installed

Done — recorded for whoever repeats or undoes it. The strip under the product title is rendered by WooCommerce, not stored in the product description, so there is nothing to paste per product. One install covers the whole catalogue.

WPCode PHP snippet

In use

Named OligoPoly — product COA banner, Auto Insert → Run Everywhere. Paste wordpress/product-coa-banner.php without its opening <?php line — WPCode supplies its own.

Paste the whole file. A truncated paste leaves the opening /** comment unclosed, and WPCode deactivates the snippet with “Unterminated comment starting line 1”. Check the last line reads } before saving.

One thing still needs your call

Live on the site right now, so this is an edit to make, not a decision to make before shipping.

The wording is firmer than the block below it

Decide

The existing opl-trust-status section on these same pages is deliberately hedged — “Product-level records where available”, “Exact-lot publishing is not yet enabled”. This banner states availability flatly, directly above it.

Fine if a COA is genuinely on file for all of them. If any is record-pending, name it and it comes off the list — one line.

Undoing it

Deactivate the snippet. The banner, both pills and their CSS disappear completely — nothing was written to product data, so there is nothing else to unwind.

What it does not touch

  • Display only. No product data, price, inventory, cart, checkout, payment, shipping, tax, or WooCommerce setting is read or written.
  • No sitewide CSS. Inline, opl-coa- prefixed, printed once per request and only on pages that render something.
  • Contrast holds. White text clears 4.5:1 (WCAG AA) against both ends of the #9333ea → #ae3ada gradient, in the banner and both pills.
  • Keyboard and motion. The banner is a real link with a visible focus ring, and honours prefers-reduced-motion.
  • Valid markup on listings. The listing pill is a <span>, not a link — that hook fires inside WooCommerce’s own product-card <a>, and a nested anchor is invalid markup browsers silently restructure.
  • The catalog pill is an attachment. /research-catalog/ is rendered by a different snippet, so its pill is generated content on the badge row that snippet already emits. If it stops emitting data-name or .oprc-badges, that pill quietly disappears; product pages and category archives are unaffected. Better long-term home: inside that snippet.
