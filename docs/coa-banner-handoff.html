How it was installed

Done — recorded here for whoever has to repeat or undo it. The strip under the product title is rendered by WooCommerce, not stored in the product description, so there is nothing to paste per product. One install covers all thirteen and adding another is one line.

Option A — WPCode / Code Snippets

Recommended

Survives theme changes and touches no theme files.

  1. Snippets → Add New → Add Your Own → PHP Snippet.
  2. Title it OligoPoly — product COA banner.
  3. Paste all of wordpress/product-coa-banner.php, without the opening <?php line — WPCode supplies it.
  4. Insertion: Auto Insert → Run Everywhere. Save and activate.

Option B — child theme

Lost on theme change

Append the same contents (minus the opening <?php) to the child theme’s functions.php. Do not put it in hello-elementor itself — the parent theme is overwritten on update.

Checking it, now or later

One product that should show the banner, one that should not. Bust the cache — the site serves cached HTML to plain requests, which is what made the banner look missing on the first check after install.

Two things still need your call

Both are live on the site right now, so these are edits to make, not decisions to make before shipping.

The wording is firmer than the block below it

Decide

The existing opl-trust-status section on these same pages is deliberately hedged — “Product-level records where available”, “Exact-lot publishing is not yet enabled”. This banner states availability flatly, directly above it.

Fine if a COA is genuinely on file for all thirteen. If any is record-pending, name it and it comes off the list — one line.

The kits inherit their single vial’s claim

Confirm

The six kits carry the same banner on the assumption that a kit ships the same material as its single vial, and therefore the same COA. If any kit is documented separately, say which.

Undoing it

Deactivate the snippet, or delete the appended block. The banner and its CSS disappear completely — nothing was written to product data, so there is nothing else to unwind.

What it does not touch

  • Display only. No product data, price, inventory, cart, checkout, payment, shipping, tax, or WooCommerce setting is read or written.
  • No sitewide CSS. The stylesheet is inline, opl-coa- prefixed, and printed once per request, only on pages that actually render a banner.
  • Contrast holds. White text clears 4.5:1 (WCAG AA) against both ends of the #9333ea → #ae3ada gradient.
  • Keyboard and motion. A real link with a visible focus ring, and it honours prefers-reduced-motion.
  • Accessible name. The visible line omits the product name — it sits under the title already, and repeating it wrapped the CTA on the longer kit titles. Screen readers still get the full name through aria-label.
  • Preview cannot drift. node build-coa-banner.js regenerates the QA preview by parsing the snippet itself, and fails rather than emitting an empty page.
